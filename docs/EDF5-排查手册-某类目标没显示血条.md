# 排查手册：某类目标没显示血条

> 这份文档是踩坑换来的。**遇到"某类敌人/目标没有血条"时，请严格按下面的顺序查**，
> 不要一上来就假设"它没被枚举到"——传送塔那次就是因为跳过了最便宜的两步，
> 白绕了五、六轮实机验证。

## 一、三步判别法（每一步都有明确的日志证据）

先开 `Debug=1` 进关卡复现，然后按顺序看：

### 第 1 步：它**被枚举**到了吗？血量**读到了**吗？

看日志里有没有它的 `[hp]` 行：

```
[hp] 新对象 <ptr> class=GeneratorPoll max=2637.6 cur=2637.6   ← 枚举到了，血量也读到了
[hp] <ptr> GeneratorPoll 2637.6 -> 2575.1 (max 2637.6 比例 98%)  ← 打它时数值在变
```

- **有 `[hp]` 行** → 枚举、血量字段都没问题，**问题在过滤或绘制**，直接进第 2 步；
- **没有 `[hp]` 行** → 才需要怀疑枚举（队伍关系、血量偏移、对象来源）。

> 传送塔的教训：它的 `[hp]` 行**当时就在日志里**，我读到了却没意识到那就是塔。

### 第 2 步：它**通过过滤**了吗？（有没有 `[bar] 画` 行）

```
[bar] 画 <ptr> class=GeneratorPoll max=2637.6 cur=2450.2 (93%)
```

- **有 `[bar] 画`** → 过滤都过了，问题在**绘制层**（位置跑出屏幕、颜色/尺寸为 0、覆盖层没画）；
- **没有 `[bar] 画`** → 被某个过滤器挡掉了，进第 3 步。

### 第 3 步：是哪个过滤器挡的？

过滤链按顺序（任何一个不满足都会跳过该目标）：

1. `Enabled=1`、热键没关掉；
2. 当前血量 > 0（活着）；
3. 当前血量 < 最大血量（**满血不画**，这是设计）；
4. 投影有效（`cw > 0.1`，在相机前方）；
5. 视野半角 `MaxViewAngle`；
6. `MaxDistance`、`MinScreenSize`；
7. 条数上限 `MaxBars`；
8. **遮挡判定** `OcclusionCheck`。

**最有效的做法：先用 ini 翻转做对照，不要写代码。**

| 做法 | 能立刻区分什么 |
|---|---|
| `OcclusionCheck=0` | 是不是遮挡判定挡的 ← **传送塔就是这一步** |
| `MaxViewAngle=120` | 是不是视野半角 |
| `MaxDistance=0`、`MinScreenSize=0` | 是不是距离/尺寸过滤 |
| `MaxBars=256` | 是不是条数上限 |
| 打它几下 | 是不是"满血不画" |

## 二、遮挡判定最容易被误伤：**自命中**

案例：**传送塔 = `. ?AVGeneratorPoll@@`**（名字完全不提示"塔"，这是最大的干扰项）。
它确实在敌方队伍里、血量为 2637.6、被打时会下降，但血条就是不出现。日志给出原因：

```
[occl] 挡住 …class=GeneratorPoll 距离=80.8m 命中比例=0.9211 判为角色=0
```

射线从眼睛射向塔的锚点，在**离你 74 m 处**（0.92 × 80.8）就命中了——**打到的是塔自己的身体**。
原因：塔这种"建筑型敌人"的**原点在身体内部**（`pos.y≈1919`，很高），射线必然穿过它自己的碰撞体；
而它的碰撞体属于"地图/建筑"层（`RayFilter=0x16` 正是这一层），于是被误判为"被墙挡住"。
蚂蚁、士兵不会如此，因为它们的锚点在其身体**上方**。

修法：`OcclusionSelfFrac`（默认 `0.90`）——**命中比例 ≥ 该值就认为打到的是目标自身，不算遮挡**。

```
OcclusionSelfFrac=0.90     ; 0.95 更严（更容易把"贴着目标的墙"当成遮挡）
```

## 三、这次的流程教训

1. **能用一行 ini 翻转验证的，绝不写代码。** 传送塔那次，`OcclusionCheck=0` 两分钟就能定位，
   却先花了五、六轮去造新的数据源（队伍 dump → 92 类白名单扫描 → 类普查）。
2. **诊断必须"自我证明"**：探针要能区分"没启动 / 没读到内存 / 匹配失败 / 校验失败"，
   而不是只给一个"命中 0"。
3. **同一个场景不要让人跑第二遍**：先把日志格式设计好，一次拿到全部所需信息。
4. 排查过程中我自己的几个 bug 也误导过判断，值得记下来：
   - `NativeProbe=4` 被夹取逻辑挡成 0（模式加了但上限没放），导致探针看似"没生效"；
   - 内存扫描在**关卡加载前**就跑完了，自然命中 0（改成"进关卡后才扫、每 15 秒重扫"）；
   - 按 RTTI 继承关系生成的 92 类白名单**漏了 `UfoCarrier508` / `GiantAnt`** 等确定存在的类，
     可信度不足 → 该方案已默认关闭，仅作备用。
